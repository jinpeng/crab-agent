# M5 Dogfood Implementation Plan

> **For agentic workers:** 这个 milestone 性质不同——不是"写新功能"，而是"**用 crab 改 crab**直到 Q2 验收"。前两个 Task 是修复 dogfood 会立刻撞上的硬伤（手工做，因为它们挡着 crab 可用）；之后的 Task 让 crab 自己产出一个 commit（Q2 验收）。

**Goal:** 达成 Q2 验收——**某次 commit 的 diff 完全由 crab 自己产生**。为此先修掉两个让 crab 不可用于真实改造的硬伤。

**Architecture:** M5 = 修复（Task 1-2，手工，因为它们挡路）+ dogfood 循环（Task 3-5，crab 主导）。修复仍走 TDD；dogfood 部分是"人驱动 crab、crab 写代码、人 review + commit"，失败记 issue 反馈进 prompt/工具。

**前置状态（已存在）：** crab v0 功能完整（M1-M4 合并，103 测试）。DeepSeek 已验证能跑 cloc 多轮工具调用 + 生成 web app。红线：crab-core 无终端 crate。cargo 需代理 `export https_proxy=http://127.0.0.1:10808`。

**本计划范围：** M5 全部。达成 Q2 即完成。

**M5 完成标志（Q2）：** git 历史里存在一个 commit，其 diff 完全由 crab（经真实 provider）产生，人只做了 review 和 `git commit`。

## 现状勘察：dogfood 会立刻撞上的两个硬伤

**硬伤 #1（致命）：`--continue` 失忆。** `Agent::new` 永远 `history: Vec::new()`；`Session::load` 从磁盘读了 entries 但 agent 的 `history`（喂 provider 的对话上下文）**不从 session 恢复**。`--continue` 之后模型完全不记得之前聊过什么。跨 run 的任务没法做。

**硬伤 #2（质量）：BASE_PROMPT 太薄。** 当前只有一句 "match exact text"，没告诉模型：(a) edit/write 前必须先 read（新鲜度门禁，否则被拒）；(b) 多处改动尽量一次 `edit` 发多个 edit；(c) edit 失败时读报错里的 `closest hint`。模型会反复撞门禁不知怎么自救。

```rust
// agent.rs tests
#[tokio::test]
async fn continued_session_restores_history_to_provider() {
    // 先建一个 session 并跑一轮
    let dir = tempfile::tempdir().unwrap();
    let path;
    {
        let provider = MockProvider::new(vec![vec![
            StreamEvent::TextDelta("first answer".into()),
            StreamEvent::StreamEnd { reason: StopReason::EndTurn },
        ]]);
        let mut tools = ToolRegistry::new();
        tools.register(Box::new(Noop));
        let session = crate::session::Session::create(dir.path()).unwrap();
        path = session.path().to_path_buf();
        let mut agent = Agent::new(Box::new(provider), tools, session, AgentConfig { max_turns: 5, ..Default::default() });
        agent.run("first question".into()).await.unwrap();
    }
    // 重新 load（模拟 --continue），新 agent 应带着旧历史
    let provider2 = MockProvider::new(vec![vec![StreamEvent::StreamEnd { reason: StopReason::EndTurn }]]);
    let mut tools2 = ToolRegistry::new();
    tools2.register(Box::new(Noop));
    let session2 = crate::session::Session::load(&path).unwrap();
    let mut agent2 = Agent::new(Box::new(provider2), tools2, session2, AgentConfig { max_turns: 5, ..Default::default() });
    agent2.run("second question".into()).await.unwrap();

    let first_call = &agent2.provider_calls()[0];
    let texts: Vec<String> = first_call.iter().flat_map(|m| &m.content).filter_map(|b| match b {
        ContentBlock::Text { text } => Some(text.clone()), _ => None
    }).collect();
    assert!(texts.iter().any(|t| t.contains("first question")), "history must include prior user msg");
    assert!(texts.iter().any(|t| t.contains("first answer")), "history must include prior assistant msg");
    assert!(texts.iter().any(|t| t.contains("second question")), "history must include new msg");
}
```

- [ ] **Step 2: 跑红** — `cargo test -p crab-core continued_session 2>&1 | grep -E 'test result|panicked' | head`，Expected: FAIL（agent2 的 history 是空的）。

- [ ] **Step 3: 实现**——`Agent::new` 从 `session.entries()` 重建 history

```rust
// Agent::new 里，把 history: Vec::new() 改为：
let history: Vec<Message> = session.entries().iter().map(|e| match e {
    crate::session::SessionEntry::Message { message, .. } => message.clone(),
}).collect();
```

注意：`session` 参数被 move 进 struct，需在 move 前先取 history，或用 `session.entries()` 在构造时读。调整字段初始化顺序。

- [ ] **Step 4: 跑绿** — `cargo test -p crab-core continued_session 2>&1 | grep 'test result'`，Expected: 1 passed。跑全套件确认不破坏现有。

- [ ] **Step 5: Commit** — `git commit -m "fix(core): --continue restores conversation history from session"`

#[test]
fn base_prompt_teaches_freshness_gate() {
    let sp = build_system_prompt(std::path::Path::new("/nonexistent"), None);
    // 必须教模型：edit/write 前先 read
    assert!(sp.to_lowercase().contains("read"), "must mention reading before editing");

- [ ] **Step 2: 跑红→绿**（改 BASE_PROMPT）

```rust
pub const BASE_PROMPT: &str = r#"You are crab, a coding agent. You have these tools: read, write, edit, bash, glob, grep.

Rules for editing files:
- ALWAYS read a file before editing or overwriting it. The edit/write tools refuse to touch a file you haven't read this session (freshness gate) — this protects against overwriting external changes.
- Use `edit` for changing existing files. Each edit's `old` must match the file EXACTLY once (no whitespace guessing). Batch multiple changes into one `edit` call's `edits` array when they're in the same file.
- If `edit` fails with "no match", re-read the file and copy the exact text from the error hint.
- Use `write` only for new files or full rewrites after a read.
- Prefer `glob`/`grep` to find files and symbols before reading whole files.

Be precise and minimal. Verify your changes compile/pass tests with `bash` when relevant."#;
```

**Placeholder scan**：Task 3 是手动验证步骤（无代码），合理——dogfood 本就是人驱动。

**Type consistency**：
- `Session::len(&self) -> usize`（Task 4 crab 要写的）需与 session.rs 现有 `entries: Vec<SessionEntry>` 一致（返回 `self.entries.len()`）。
- `Agent::new` 从 `session.entries()` 重建 history：`SessionEntry::Message { message, .. }` 模式与 session.rs 一致。

**已知坑（给执行者）**：
- Task 1 的 `Agent::new` 改动要注意 `session` 被 move 进 struct 前先取 history（`let history = ...; Self { session, history, ... }`），否则 borrow-after-move。
- Task 3/4 需要真实 DeepSeek API key + base_url。
- dogfood 时权限确认会频繁弹出（bash/edit 都弹），烦的话用 `--yolo`（dogfood 自己仓库、改动可 git 反悔，相对安全）。
- Task 4 若 crab 反复撞新鲜度门禁（不 read 就 edit），说明 Task 2 的 prompt 还不够——把现象记进 dogfood-log，迭代 prompt。

**这个计划与前几个的本质区别**：Task 1-2 是手工修复（crab 还不能可靠修自己的硬伤）；Task 4-5 才是 crab 主导。Q2 验收的判定是客观的——git 历史里有 crab 产的 commit。
